## 5. Recommendation — minimal tldraw editor over Agent Starter Kit

**Decision: build the renderer as a minimal custom tldraw integration using the programmable `Editor` API; do NOT start from the Agent Starter Kit (tldraw template).**

| Criterion | Minimal editor (Editor API) | Agent Starter Kit |
|---|---|---|
| Control loop | We drive the canvas imperatively from the event loop (`editor.createShape`, `updates`, etc.) | Kit owns a chat turn loop and an agent action system around it |
| Latency model | Events can land on the canvas at stream rate — matches our per-event p50/p95 ambition | Adds a chat-message round trip; chat-centric, not continuous duplex (SOURCES item 2) |
| Dependencies | `tldraw`, `react`/`react-dom` only | `ai` SDK + model providers (`@ai-sdk/anthropic`, `@openrouter/ai-sdk-provider`, `@google/generative-ai`…) — pulls paid-model calls and key config by default |
| Budget constraint | $0 offline-first (ATLAS_HANDOFF) | Requires provider API keys (`.dev.vars`) for its default path |
| Schema fit | We implement PROTOCOL visual proposals → shape ops narrowly | Kit's action/mode manager is a parallel abstraction we'd have to bypass |

Sources: [tldraw SDK repo](https://github.com/tldraw/tldraw), [Agent Starter Kit docs](https://tldraw.dev/starter-kits/agent) (explicitly names a **chat panel** and streaming chat responses; uses `ai` SDK + `OPENROUTER_API_KEY`), [beginner tldraw](https://tldraw.dev/) (programmatic `onMount` Editor example), `VISUAL_RUNTIME.md` guidance that tldraw is the canvas, not the semantic model. Starter Kit is useful later as a *reference* for Editor API patterns, not as our runtime base.

**Rendering stack decision (from VISUAL_RUNTIME.md + SOURCES):** TypeScript + React + tldraw first; add Motion SVG only if basic CSS/SVG transitions prove insufficient — not by default. tldraw handles shapes, camera, selection, history; numeric controls (`revealProgress/attention/layoutWeight/nodeCount`) map to shape properties/styles; fallback for any un-rendered semantic → neutral text/card, never a falsely-grounded picture.
