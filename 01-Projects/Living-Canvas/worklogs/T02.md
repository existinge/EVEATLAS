# T02 — Deterministic coordinator / stoplight backplate (Gate P2 evidence)

Date: 2026-11-11. Builder session evidence: Gate P2 verified GREEN, 29/29. Authoritative files in `runtime/src/`; commit on branch `feat/living-canvas-t02-coordinator`.

## Gate P2 objective

The coordinator receives fast-decider proposals, validates them against canonical semantic state with a pure GREEN/YELLOW/RED stoplight, and commits **only** coordinator-authorized scene actions. Interruptions invalidate outstanding speculative actions without destroying the stable scene; corrections revert dependent provisional changes via event provenance; idempotency preserves proposal-creation vs scene-commitment vs legitimate-reversal; concurrency/monotonicity ensure stale results cannot overwrite a newer topic epoch or semantic revision. Only the coordinator may authorize new scene commits — an externally supplied `SCENE_COMMITTED` cannot bypass authority.

## Implementation

- `runtime/src/coordinator.ts` — `validateProposal(proposal, snapshot)` is pure. RED = any hard failure. GREEN = no hard failures AND authoritative evidence AND (`payload.reversible` → `commitOnAuthority`). YELLOW = no hard failures but incomplete evidence or a preview-grade action (emphasize / deEmphasize / revealHint) → `stageProvisional` (reversible, never a factual commit). `externalCommit` enforces the coordinator grant: `not-coordinator-authoritative` without a grant, `authority-fingerprint-mismatch` on divergence (grant revoked), and an authority-lineage gate refusing a second *distinct* `SCENE_COMMITTED` for an already-committed proposal. `latencyReport()` separates coordinator hops from any model work.
- `runtime/src/reducer.ts` — `applyCommittedScene` (SCENE_COMMITTED): no matching pending proposal → probe committed scene actions; already committed → `skipped-duplicate`/`proposal-already-committed`; expired → `expired-proposal`; otherwise → `no-valid-source`. Mutates canonical state in place deterministically (commitId = SHA-256 of JSON state + applied event ids; no wall-clock in canonical JSON).
- `runtime/src/store.ts` — schema-parse → session scoping → duplicate-eventId dedup → `reduceState`; bounded subscriber queue preserves CRITICAL_KINDS.
- Tests: `runtime/src/gate-p2-coordinator.test.ts` (29 tests), `runtime/src/gate-p1.test.ts` (16 tests, no-regression).

## The idempotency/authority discriminator

P2.4 requires a **repeated** GREEN commit (`skipped-duplicate`) while P2.4b requires a **second, distinct** `SCENE_COMMITTED` for the same proposal to stay refused (`no-valid-source`). Resolution by layer:
- reducer store path: an already-committed proposalId returns `skipped-duplicate`/`proposal-already-committed` (P1.2c, P2.4 replay);
- coordinator `externalCommit`: a genuinely distinct inbound `SCENE_COMMITTED` for an already-committed proposal whose eventId is not already applied is refused `no-valid-source` (P2.4b).
A `skipped-duplicate` returned by the reducer flows verbatim and does not mark `committedByCoordinator`. The outer grant fingerprint gate (P2.5, P2.5b) is untouched. Result: an exact replay of an already-applied action is idempotent; re-inventing a second scene action is never silently accepted.

## Observations / risks

- `sceneRevision` in records is the envelope-declared revision rolled up with `max`; a coordinator-authored commit carries the pre-commit snapshot revision, so it does not act as an incrementing commit counter. No P1/P2 test depends on an incrementing scene revision; documented here rather than silently redesigned.
- Tests are scripted deterministic event flows (labeled SIMULATED by nature): they prove the deterministic pipeline, not conversational intelligence or live duplex.
- Authority invariant (I1/PROTOCOL) is exercised directly by P2.4b, P2.5, P2.5b and P2.5c — an externally supplied `SCENE_COMMITTED` cannot create a scene action.
- No credentials, tokens, or private data in the runtime tree; branch contains only code, fixtures, tests and worklogs.
