## Gate P1 — mandatory cases

- Deterministic replay: two independent replays of a fixture produce byte-identical canonical snapshots and commit IDs (P1.1).
- Duplicate event IDs never double-apply (P1.2); duplicate proposal IDs are skipped without re-adding (P1.2b); a repeated `SCENE_COMMITTED` for an already-committed proposal is idempotent (`skipped-duplicate`) (P1.2c).
- Unknown event kind and malformed JSON surface `schema-invalid` — never silent acceptance (P1.3, P1.3b, P1.3c).
- Late old-epoch event cannot mutate the current scene (P1.4).
- High-frequency provisional observations coalesce; `USER_INTERRUPT`/critical events are never dropped under a full bounded queue (P1.5, P1.5b, P1.5c).
- Unrecognized multilingual speech stays `NEEDS_PLAN`, never hallucinated (P1.6).
- Observation/semantic/scene revisions advance independently (P1.7).
- `DECIDER_PROPOSAL` is advisory-only; nothing commits without `SCENE_COMMITTED` (P1.8).
- Corrections revoke dependent provisional proposals (P1.8b); epoch advance does not inherit old-topic provisional permissions (P1.9).

## P1.2c closure (this session)

A repeated `SCENE_COMMITTED` with a **distinct eventId and identical payload** was returned as `rejected`/`no-valid-source` instead of the required `skipped-duplicate`. Classified inside `reducer.applyCommittedScene`: when a committed scene action already exists for the proposalId, the no-match branch now returns `{status:"skipped-duplicate", reason:"proposal-already-committed"}` instead of `no-valid-source`. The `no-valid-source` return is retained for proposals that never existed. This keeps authority semantics intact: only an exact replay of an already-applied commitment is idempotent; a genuinely distinct re-invention remains rejected (see the T02/P2.4b discriminator, which is enforced at the coordinator layer).
